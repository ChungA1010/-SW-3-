17번 BEATs Axis Intensity 모델 설명서

17번 모델은 하나의 모델이 모든 이펙터를 한 번에 맞히는 구조가 아니라, dist, phaser, delay를 각각 독립 모델로 학습하고 세 결과를 합쳐 해석하는 구조다. 현재 학습 클래스는 off, 50, 100 세 단계만 사용한다.

모델 3개: drive / phase / space 대상 이펙터: dist / phaser / delay 강도: off / 50 / 100 데이터: single_effect + multi_effect 모바일 대응 탭 문서

처음에는 탭만 보고 필요한 곳을 누르면 된다

핵심 요약

17번은 dist, phaser, delay만 분석하는 모델이다. 각각은 서로 다른 독립 모델로 학습된다. 그래서 실제 결과는 세 질문의 답으로 나온다.

drive 모델

dist가 꺼짐인지, 50인지, 100인지 맞힌다.

phase 모델

phaser가 꺼짐인지, 50인지, 100인지 맞힌다.

space 모델

delay가 꺼짐인지, 50인지, 100인지 맞힌다.

Clean 판정

세 모델 결과가 모두 off이면 Clean으로 해석한다. 별도의 clean 전용 모델이 있는 것이 아니라, 세 축이 모두 꺼진 상태를 Clean으로 보는 방식이다.

질문 현재 답
이외의 이펙터도 학습하나? 아니다. chorus, reverb, fuzz, flanger, tremolo, drive 등은 제외한다.
25, 75 강도는 쓰나? 쓰지 않는다. 현재 클래스는 off, 50, 100 세 개다.
멀티 이펙터는 어떻게 학습하나? 같은 오디오를 세 모델이 각자 자기 축의 정답으로 본다. 예: dist_50_delay_100_phaser_50은 drive=50, space=100, phase=50이다.

모델 구조

17번은 앙상블처럼 보이지만, 실제로는 같은 구조의 모델을 축별로 세 번 학습하는 방식이다. 각 모델은 BEATs 백본으로 오디오 특징을 뽑고, attention pooling 후 3클래스 head로 강도를 예측한다.

1WAV 입력

오디오를 16kHz mono로 로드한다.

23초 구간

훈련 시 3초로 자르거나 패딩한다.

3BEATs

시간축 특징 벡터를 추출한다.

4Pooling

중요한 프레임에 가중치를 둬 하나의 벡터로 합친다.

5Head

off/50/100 중 하나를 출력한다.

dist 모델   : audio -> BEATs -> pooling -> drive head -> off / 50 / 100
phaser 모델 : audio -> BEATs -> pooling -> phase head -> off / 50 / 100
delay 모델  : audio -> BEATs -> pooling -> space head -> off / 50 / 100
왜 세 모델인가?

멀티 이펙터에서는 dist, phaser, delay가 동시에 켜질 수 있다. 하나의 단일 클래스 분류기로 만들면 조합 수가 늘어나고 새 조합에 약해진다. 축별 모델은 “내 이펙터가 얼마나 걸렸는가”만 학습하므로 멀티 조합을 더 자연스럽게 다룬다.

데이터와 라벨

학습 데이터는 기본적으로 single_effect와 multi_effect 두 폴더를 함께 읽는다. 단, 현재 목표에 맞지 않는 이펙터나 강도는 학습에서 제외한다.

구분 사용 제외
이펙터 dist, phaser, delay chorus, reverb, fuzz, flanger, tremolo, drive
강도 off, 50, 100 25, 75
Clean 세 축이 모두 0 없음

single_effect 처리

폴더 구조가 Clean, Drive, Phase, Space인 데이터를 읽는다. 예를 들어 Drive/dist_100_...는 drive=100이고 phase/space는 off가 된다. 

Clean/...                 -> drive=off, phase=off, space=off
Drive/dist_50_...         -> drive=50,  phase=off, space=off
Phase/phaser_100_...      -> drive=off, phase=100, space=off
Space/delay_50_...        -> drive=off, phase=off, space=50

multi_effect 처리

파일명 안의 effect_intensity 쌍을 찾아 세 축 라벨로 바꾼다. 같은 파일 하나가 세 모델 학습에 모두 들어갈 수 있지만, 각 모델이 보는 정답은 다르다. 

dist_50_delay_100_phaser_50_....wav

drive 모델  -> 정답 50
phase 모델  -> 정답 50
space 모델  -> 정답 100
오염 방지 규칙

multi_effect 파일명에 지원하지 않는 이펙터나 25/75가 하나라도 섞이면 그 파일 전체를 제외한다. 그래야 reverb가 들어간 파일을 “delay off” 예제로 잘못 배우는 문제를 줄일 수 있다.

학습 흐름

python train.py --axis all을 실행하면 세 축을 한 번에 병렬 학습하는 것은 아니고, drive를 끝낸 뒤 phase, 그다음 space 순서로 학습한다.

1데이터 스캔

두 폴더에서 사용 가능한 WAV만 수집한다.

2라벨 생성

각 파일을 drive/phase/space 레벨로 변환한다.

3분할

train/valid를 만들고 split json을 저장한다.

4학습

축별 모델을 학습하고 best/latest 체크포인트를 저장한다.

5검증

valid 파일 단위 예측 CSV와 metrics json을 만든다.

생성 파일 역할
artifacts/drive_best_model.pt drive 모델의 최고 성능 체크포인트
artifacts/drive_latest_training.pt 중간에 끊겼을 때 이어가기 위한 최신 학습 상태
artifacts/drive_split.json train/valid에 어떤 파일이 들어갔는지 기록
outputs/drive/val_file_level_drive_predictions.csv valid 파일별 실제값, 예측값, confidence 기록
resume 동작

--resume을 붙이면 *_latest_training.pt에서 이어간다. 하지만 5단계 클래스였던 예전 체크포인트처럼 현재 off/50/100 스키마와 다르면 자동으로 새로 시작한다.

파일과 함수

아래 버튼을 누르면 해당 파일의 역할과 주요 함수 설명만 보인다. 17번 코드를 볼 때는 config.py에서 기준을 잡고, dataset.py, train.py, utils.py 순서로 보면 이해가 빠르다.

공부 순서 한 줄 요약

config.py에서 “무엇을 학습할지”를 확인하고, dataset.py에서 “파일명이 어떻게 정답 라벨이 되는지”를 본 다음, model.py에서 “오디오가 어떤 신경망을 통과하는지”를 보고, train.py와 utils.py에서 “학습 루프가 어떻게 돌아가는지”를 따라가면 된다. 마지막으로 infer.py, infer_folder.py에서 학습된 모델이 실제 파일을 어떻게 분석하는지 확인하면 전체가 연결된다.

전체 코드를 이해하는 추천 순서

1. config.py - 실험의 규칙표

여기서는 모델이 배울 세계를 정의한다. 현재 세계는 dist, phaser, delay 세 이펙터와 off/50/100 세 강도뿐이다. 이 파일을 먼저 보면 나머지 코드에서 왜 3개 축, 3개 클래스가 반복되는지 이해된다.

  • AXIS_NAMES는 학습할 모델 종류를 정한다.
  • EFFECT_TO_AXIS는 파일명 이펙터를 drive/phase/space 축으로 바꾼다.
  • CLASS_SCHEMA는 현재 모델이 3단계 모델인지 확인하는 기준이다.
2. dataset.py - WAV 파일을 정답 문제로 바꾸는 곳

모델은 파일명을 직접 이해하지 못한다. 그래서 dataset.py가 dist_50_delay_100... 같은 이름을 읽어 drive=50, phase=off, space=100 같은 숫자 정답으로 바꾼다.

  • scan_dataset()이 폴더를 훑으며 WAV를 찾는다.
  • _parse_single_effect_record()는 single_effect 구조를 해석한다.
  • _parse_multi_effect_record()는 multi_effect 파일명 조합을 해석한다.
  • AxisWaveformDataset.__getitem__()은 학습 순간에 오디오와 정답 라벨을 꺼낸다.
3. model.py - 정답을 맞히는 신경망 모양

여기서 “오디오가 들어가서 3개 점수로 나오는 길”을 만든다. BEATs가 소리 특징을 뽑고, pooling이 중요한 시간 구간을 모은 뒤, head가 off/50/100 점수를 만든다.

  • BEATsAxisIntensity 하나가 축 하나를 담당한다.
  • drive, phase, space는 같은 구조지만 서로 다른 체크포인트로 따로 학습된다.
  • 마지막 Linear(256, 3) 때문에 출력 클래스가 3개다.
4. train.py - 학습 버튼을 눌렀을 때의 지휘자

사용자가 python train.py --axis all을 실행하면 여기서 시작한다. CLI 옵션을 읽고, 데이터셋을 만들고, 축별로 train_one_axis()를 호출한다.

  • main()은 전체 실행 순서를 잡는다.
  • train_one_axis()는 축 하나의 split, model, loss, optimizer, 학습, 검증 저장을 연결한다.
  • --resume은 latest checkpoint와 현재 class schema가 맞을 때만 이어간다.
5. utils.py - 실제로 epoch를 돌리는 엔진

train.py가 지휘자라면 utils.py는 실제 작업자다. batch를 GPU에 올리고, loss를 계산하고, backprop을 하고, valid 점수를 계산하고, best checkpoint를 저장한다.

  • _run_epoch()가 train/valid 한 epoch를 실제로 돈다.
  • fit_axis_model()이 epoch 반복, best 저장, latest 저장, early stopping을 담당한다.
  • predict_axis_file()은 학습 후 파일 하나를 sliding window로 분석한다.
6. infer.py / infer_folder.py - 완성된 모델을 사용하는 곳

학습이 끝나면 drive_best_model.pt, phase_best_model.pt, space_best_model.pt 세 파일이 생긴다. 추론 스크립트는 이 세 모델을 로드해서 같은 오디오를 각각 분석하고 결과를 합친다.

  • infer.py는 파일 하나를 JSON으로 분석한다.
  • infer_folder.py는 폴더 전체를 CSV로 정리한다.
  • 세 축이 모두 off이면 Clean으로 해석한다.

학습 명령어가 실제로 지나가는 함수 흐름

python train.py --axis all을 실행했을 때의 큰 흐름이다.

  1. train.py/main()이 옵션을 읽고 GPU/CPU를 선택한다.
  2. dataset.py/scan_dataset()이 single_effect, multi_effect에서 학습 가능한 WAV를 찾는다.
  3. dataset.py/create_train_val_split()이 train/valid 파일 목록을 만든다.
  4. train.py/train_one_axis("drive")가 drive 모델 학습을 시작한다.
  5. utils.py/create_dataloaders()가 WAV를 batch로 공급할 준비를 한다.
  6. utils.py/build_model()이 model.py/BEATsAxisIntensity를 만든다.
  7. utils.py/fit_axis_model()이 여러 epoch를 돌리고 최고 모델을 저장한다.
  8. drive가 끝나면 같은 과정을 phase, space에 반복한다.
  9. 마지막에 outputs/axis_training_summary.json에 세 축 결과 요약을 저장한다.

추론 명령어가 실제로 지나가는 함수 흐름

python infer_folder.py --input-dir ...를 실행했을 때의 큰 흐름이다.

  1. infer_folder.py/main()이 입력 폴더와 artifact 폴더를 확인한다.
  2. load_axis_model()이 drive/phase/space 체크포인트를 각각 로드한다.
  3. iter_audio_files()가 분석할 WAV 파일 목록을 만든다.
  4. 각 WAV마다 utils.py/predict_axis_file()을 세 번 호출한다.
  5. predict_axis_file()은 긴 오디오를 여러 window로 나누고, 각 window 예측을 평균낸다.
  6. 세 축 결과를 한 줄로 합쳐 axis_folder_inference.csv에 저장한다.

config.py

실험 전체의 기준값을 모아둔 파일이다. 어떤 데이터 폴더를 읽을지, 어떤 이펙터와 강도를 학습할지, 출력 파일 이름은 어떻게 만들지 결정한다.

AXIS_NAMES

drive, phase, space 세 축 이름이다. 학습과 추론 루프가 이 목록을 기준으로 돈다.

TARGET_EFFECTS

현재 학습 대상 이펙터다. dist, delay, phaser만 포함한다.

INTENSITY_LEVEL_TO_DISPLAY

내부 숫자 라벨을 화면 표시로 바꾼다. 0=off, 1=50, 2=100이다.

EFFECT_TO_AXIS

파일명 이펙터를 축으로 바꾼다. dist->drive, phaser->phase, delay->space.

CLASS_SCHEMA

현재 클래스 체계를 저장한다. resume 체크포인트가 예전 5단계 모델인지 확인하는 안전장치에 쓰인다.

artifact_path_for_axis()

축 이름을 받아 artifacts/{axis}_best_model.pt 경로를 만든다.

dataset.py

WAV 파일을 찾아 학습 가능한 레코드로 바꾸는 파일이다. 17번 모델에서 가장 중요한 라벨링 로직이 여기에 있다.

AxisRecord

파일 하나의 경로와 세 축 라벨을 담는다. 예: drive=1, phase=0, space=2.

AxisRecord.target_for_axis(axis_name)

현재 학습 중인 축의 정답만 꺼낸다. drive 모델이면 drive_level, phase 모델이면 phase_level을 반환한다.

_parse_single_effect_record()

single_effect 폴더형 데이터를 해석한다. Clean은 세 축 모두 0, dist_50은 drive=1처럼 만든다.

_parse_multi_effect_record()

multi_effect 파일명에서 dist_50, delay_100, phaser_50 같은 쌍을 찾는다. 지원하지 않는 이펙터나 25/75가 있으면 제외한다.

scan_dataset()

하나 또는 여러 데이터 폴더를 받아 WAV를 전부 훑고, 학습 가능한 AxisRecord 목록을 만든다.

create_train_val_split()

축별 라벨 분포를 유지하면서 train/valid를 나눈다. 가능하면 group-aware split을 사용해 비슷한 riff가 train과 valid에 갈라져 섞이는 문제를 줄인다.

AxisWaveformDataset.__getitem__()

실제 학습 시 파일을 로드하고 3초 길이로 맞춘 뒤, 현재 축의 정답 라벨과 함께 반환한다.

model.py

실제 신경망 구조가 들어 있다. BEATs 백본, attention pooling, 3클래스 head가 여기서 만들어진다.

build_default_beats_config()

pretrained checkpoint가 없을 때 BEATs 구조 설정을 만든다. 지금 로그에서 pretrained를 못 찾으면 이 설정으로 랜덤 초기화된다.

MaskedAttentionPooling

BEATs가 뽑은 시간 프레임별 특징 중 어떤 프레임이 중요한지 점수를 매기고, weighted sum으로 하나의 벡터를 만든다.

BEATsAxisIntensity.__init__()

축 이름과 pretrained 경로를 받아 백본과 head를 만든다. 마지막 출력층은 현재 3개 클래스다.

BEATsAxisIntensity.forward()

오디오 tensor를 받아 BEATs 특징 추출, pooling, head 통과 후 logits를 반환한다.

train.py

명령어 실행 진입점이다. 데이터 스캔, 모델 생성, 학습, 검증, 결과 저장을 연결한다.

main()

CLI 옵션을 읽고, device를 고르고, 데이터셋을 스캔한 뒤 --axis all이면 세 축을 순서대로 학습한다.

train_one_axis()

축 하나에 대한 전체 학습을 담당한다. split 생성, dataloader 생성, 모델 생성, loss/optimizer/scheduler 생성, 학습 실행, 최종 저장까지 처리한다.

--resume

latest checkpoint가 있으면 이어간다. 단, 현재 클래스 체계와 다르면 예전 체크포인트를 무시하고 새로 시작한다.

--data-dir

여러 데이터 폴더를 받을 수 있다. 기본값은 single_effect와 multi_effect다.

utils.py

학습 루프와 추론 도우미가 들어 있다. 실제 epoch 진행과 metrics 계산은 대부분 이 파일에서 수행된다.

create_dataloaders()

train/valid dataset을 DataLoader로 감싼다. train 쪽은 클래스 균형을 맞추기 위해 WeightedRandomSampler를 쓴다.

build_model()

BEATsAxisIntensity를 만드는 얇은 래퍼다. train과 inference가 같은 방식으로 모델을 만들게 해준다.

class_weights_from_labels()

클래스별 데이터 수 차이를 loss weight로 보정한다. 현재는 3클래스 기준이다.

_run_epoch()

한 epoch의 train 또는 valid를 돈다. batch loss 로그를 찍고, accuracy, macro F1, on/off accuracy를 계산한다.

fit_axis_model()

여러 epoch를 돌리는 핵심 학습 함수다. best checkpoint와 latest training checkpoint를 저장하고 early stopping도 여기서 처리한다.

predict_axis_file()

파일 하나를 sliding window로 나누어 각 구간 예측을 평균낸 뒤 최종 off/50/100 결과를 만든다.

evaluate_axis_records()

valid 파일들을 다시 파일 단위로 추론해 CSV와 metrics JSON을 저장한다.

infer.py

WAV 파일 하나를 세 모델로 분석하는 스크립트다.

load_axis_model()

축별 *_best_model.pt를 읽고, 저장된 backbone config와 state dict로 모델을 복원한다.

main()

drive, phase, space 모델을 모두 로드하고 하나의 오디오 파일에 대해 세 축 결과를 JSON으로 출력한다.

infer_folder.py

폴더 안 WAV 파일들을 한꺼번에 분석해 CSV로 정리하는 스크립트다.

iter_audio_files()

입력 폴더에서 WAV 파일 목록을 만든다. --recursive를 주면 하위 폴더까지 본다.

load_axis_model()

축별 체크포인트를 로드한다. 누락된 체크포인트가 있으면 오류를 낸다.

main()

각 파일에 대해 세 축 모델을 실행하고, 화면 로그와 axis_folder_inference.csv를 만든다.

수치 해석

학습 로그에서 주로 볼 값은 val_acc, val_onoff_acc, val_f1, score다.

수치 의미 판단 방법
val_acc off/50/100을 정확히 맞힌 비율 가장 직관적인 성능. 50과 100을 헷갈리면 떨어진다.
val_onoff_acc 켜짐/꺼짐을 맞힌 비율 실사용에서 “이 이펙터가 켜졌나?”를 보는 데 중요하다.
val_f1 클래스별 균형을 고려한 점수 특정 클래스만 잘 맞히는지 확인할 때 중요하다.
score best checkpoint 저장 기준 0.45*F1 + 0.30*onoff + 0.25*acc로 계산된다.
멀티 데이터에서 낮아질 수 있는 이유

멀티 파일은 dist, phaser, delay가 섞여 있으므로 한 이펙터의 특징이 다른 이펙터에 가려질 수 있다. 단일 테스트보다 어려운 것이 정상이고, 실제 사용 상황을 잘 버티는지 보는 기준으로 삼으면 된다.

추론 결과 해석

추론 결과는 세 축이 각각 intensity_display와 confidence를 갖는다. 모든 축이 off면 Clean, 하나 이상 켜져 있으면 해당 이펙터가 켜진 것으로 해석한다. 

{
  "format_version": "axis-ensemble-v1",
  "mode": "three_independent_axis_models",
  "dominant_axis": "space",
  "axes": {
    "drive": {"detected": false, "intensity_display": "off"},

drive=50, phase=50, space=100 dist 50 + phaser 50 + delay 100

주의점

모바일 탭 동작 CSS/JS만 사용 인터넷 필요 없음 HTML 단독 실행 가능

1. 이전 5단계 체크포인트와 호환되지 않음

현재 모델 head는 3클래스다. 예전 off/25/50/75/100 모델 체크포인트를 그대로 로드하면 구조가 맞지 않는다. 그래서 코드에 class schema 검사를 넣어 예전 resume을 자동으로 피하게 했다.

2. multi_effect 데이터는 실제로 더 어렵다

여러 이펙터가 섞이면 각 축의 특징이 가려질 수 있다. 따라서 single 테스트보다 multi 테스트가 낮게 나와도 이상한 현상은 아니다.

3. Clean은 독립 클래스가 아니다

Clean 전용 출력 하나가 있는 구조가 아니라, 세 축이 모두 off일 때 Clean으로 해석하는 구조다. 이 차이를 알고 있어야 결과를 정확히 읽을 수 있다.

4. 25/75 데이터는 학습에서 빠진다

현재 목표가 off/50/100이므로 25/75는 중간값으로 흡수하지 않고 제외한다. 억지로 25를 50으로, 75를 100으로 바꾸면 라벨 노이즈가 생길 수 있다.
